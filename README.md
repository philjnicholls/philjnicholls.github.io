# philjnicholls.com

A one-page portfolio generated by a small Python script. There's nothing to run
on the server: `build.py` renders static HTML and CSS into `dist/`, and any
static host can serve that folder.

## Build

```bash
pip install -r requirements.txt
python build.py            # renders dist/
python build.py --serve    # renders, then previews at http://localhost:8000
```

## Edit

| To change | Edit |
| --- | --- |
| Any text, links, phone number, jobs, projects, skills | `content/site.yaml` |
| Page structure | `templates/index.html` (sections), `templates/base.html` (head, nav, footer) |
| Colours, fonts, spacing | `static/css/site.css` (tokens at the top) |
| Profile photo | `static/img/phil.jpg` and `phil.webp` (480 × 600) |
| Hero map | `contour_paths()` and `flight_track()` in `build.py` |

Set `phone: ""` in `site.yaml` to hide the phone number, or `photo: ""` to hide
the portrait. To add a project, add another entry under `projects:`.

## Deploy

Pushing to `main` publishes the site to GitHub Pages at
[philjnicholls.com](https://philjnicholls.com). The workflow in
`.github/workflows/deploy.yml` runs `build.py` and deploys `dist/`; there's
nothing to commit by hand. To redeploy without a new commit, run it from the
Actions tab ("Deploy to GitHub Pages" → "Run workflow") or with:

```bash
gh workflow run deploy.yml
```

The custom domain is set in the repository's Pages settings, so `dist/` needs
no `CNAME` file. Pages must have its source set to "GitHub Actions"
(Settings → Pages → Build and deployment).

Elsewhere, upload the contents of `dist/` to any static host, for example:

```bash
rsync -avz --delete dist/ user@server:/var/www/philjnicholls.com/
```
